Meridian

Multi-team project intelligence that remembers what was promised.

Jira shows current state.
Meridian remembers commitments —
and tells each team when one breaks.

Demo project: BarkPark — a dog park app built by 3 teams, mid-release.

The scenario · June 5, midway through Phase 2

Dana — director. Wants the release funded and on time.

Marisol — design manager. Drives the feature set.

Kai — designer. Owns every screen.

Priya — backend (Go). Promised: "map API final at current scope by June 19."

Tom — frontend (Svelte). Downstream of everyone.

The mid-cycle requirement

To fund the app, Design — guided by the director — adds paid veterinarian placements to the map. Four new issues land in the middle of Phase 2.

The question Jira can't answer: whose promises did that just break?

Four tools, one loop

Butterbase

System of record — teams, phases, issues, dependency graph.

Live cloud DB, provisioned & seeded via MCP today.

XTrace

Institutional memory — scoped commitments; new facts reconciled against old promises.

Live — the scope-change contradiction is recalled from memory in the demo.

RocketRide

Analysis pipeline — multi-agent rollup over the dependency graph.

Pipeline defined; deterministic fallback engine runs the demo.

Photon

Messaging — channel briefings out, plain-language replies in.

Spectrum SDK live; Slack gated by vendor — terminal provider stands in.

issue data → memory check → rollup → #design · #backend · #frontend · #management → reply updates the plan

Live demo

1 · board.html — the release, before (browser tab)
2 · team → scope-change — the requirement lands; every channel learns what it means for them (terminal)
3 · npm run board + refresh — teal cards: the scope change, visible (browser)
4 · push issue #15 to phase 3 — a manager fixes it by replying in chat (terminal)
5 · exit

What Meridian knows that a tracker doesn't

🧠 What each team promised — with scope, as facts in memory

⚡ When a new requirement contradicts a promise — automatically

🧭 Who downstream is affected — via the dependency graph

💬 And it tells each audience in their channel — fix applied by reply, no dashboard
